========================================================================
 RTF COMPARISON TOOL  -  START HERE (Mac)
========================================================================

WHAT IT DOES
  Compares two RTF files and reports how their CONTENT differs, ignoring
  cosmetic formatting (fonts, spacing, column widths). It tells you the
  files are EQUIVALENT, or lists every difference with its row/column.

WHAT YOU NEED
  - macOS
  - R installed. Either:
        * download from https://cran.r-project.org  (the .pkg installer), or
        * if you use Homebrew:  brew install --cask r
  - No administrator rights are needed to RUN the tool.

------------------------------------------------------------------------
 STEP 0  -  UNZIP
------------------------------------------------------------------------
  Double-click the ZIP in Finder to extract it. Keep the whole extracted
  folder together; don't move files out of it.

  First time you open a launcher, macOS may say it is "from an
  unidentified developer". This is normal and needs NO admin:
        right-click (or Control-click) the file -> Open -> Open.
  After that, it opens on a normal double-click.

  If a launcher won't run at all, open the Terminal app, type  cd  and a
  space, drag the "macos" folder onto the window, press Enter, then run:
        chmod +x *.command
  (You only ever need this once.)

------------------------------------------------------------------------
 STEP 1  -  ONE-TIME SETUP  (first time only; needs internet)
------------------------------------------------------------------------
  Open the "macos" folder and double-click:

        1-Install-Packages.command

  A Terminal window installs 5 small R packages. Wait for  SUCCESS ,
  then press any key to close. You only do this once per computer.

------------------------------------------------------------------------
 STEP 2  -  COMPARE TWO FILES  (by pasting their paths)
------------------------------------------------------------------------
  In the "macos" folder, double-click:

        2-Compare-RTF-Files.command

  It asks for two file paths. For each one, the easiest way to get the
  path is to DRAG the RTF file from Finder onto the Terminal window (that
  pastes its full path), then press Enter. (Or in Finder: right-click the
  file, hold the Option key, choose "Copy ... as Pathname", then paste.)

      File 1 (Set 1) : <drag/paste the first path>   [Enter]
      File 2 (Set 2) : <drag/paste the second path>  [Enter]

  The first file you select is always Set 1. The second is always Set 2.

  The result appears immediately on screen:
        "EQUIVALENT"            = no content differences, or
        "N difference(s) found" = they differ (each one is listed)

  NOTHING is saved automatically. After the result it asks:

        Export report?  [t] TXT   [c] CSV   [b] both   [Enter] skip :

  Press Enter to skip, or pick a format. If you export, it then asks WHERE
  to save - type or paste a full path (or a folder), for example
        /Users/you/QC/table_compare.txt
  and only that file is written. (TXT = the full report; CSV = just the
  differences, for Excel/Numbers.)

  At the end it also asks:

        "Would you like a separate set of RTF tables generated showing only
         the differences or no differences identified line by line?"

  Answer Yes to create change tables in the style of each source RTF. The
  calculation direction is Set 2 minus Set 1. Generated data cells contain
  only NC, a signed count/percentage-point change such as (+5, -1%), a signed
  scalar change such as +1.5, CHG, or an ONLY IN SET marker.

  Original headers are preserved and receive Change or NC on a new line. The
  table number receives "_Change". Rows are matched by Column 1 descriptions,
  and materially changed Set 2 footnote text is shown in parentheses. The
  generated files keep their original names with "_change" before .rtf and
  are saved inside the tool under:

        logs/RTF Changes/Set 1/
        logs/RTF Changes/Set 2/

  For a folder comparison, progress is printed for every accepted pair. The
  final message states how many pairs completed. If even one accepted pair
  fails to create both validated RTFs, the run is marked INCOMPLETE instead
  of presenting a partial folder as successful.

  It then asks "Compare another pair? (y/N)" so you can keep going.
  Works with ANY two RTF files anywhere on the computer.

  Prefer clicking files in a dialog instead of pasting paths?
        Double-click  2b-Compare-Using-File-Picker.command  instead.

------------------------------------------------------------------------
 STEP 3  -  COMPARE A WHOLE FOLDER AT ONCE  (batch)
------------------------------------------------------------------------
  To check many tables in one go, double-click:

        2c-Compare-Folders.command

  Two folder pickers open. Choose the FIRST folder (Set 1), then the SECOND
  folder (Set 2). The tool compares EVERY .rtf file in the first
  folder against its corresponding file in the second folder. Exact names
  are matched first. A file may also be paired when its name differs slightly
  and there is one clear, highly similar match in the same relative subfolder.

  You get ONE report that lists EVERY file - including the ones that are
  EQUIVALENT - so it is a complete record of the whole set. Files that
  differ have their differences listed; files found in only one folder are
  flagged. The full report is saved automatically inside the tool's
  "logs/reports" folder, and you are also offered a Save dialog to keep your
  own copy wherever you like.

  At the end, the same change-table question appears. Answer Yes to generate
  change RTFs for every successfully compared filename pair. Exact names take
  priority. A like-name match must be unique, within 3 character edits, at
  least 85% similar, and clearly better than any alternative. Names are also
  split at each "0" so related families such as s0exp0sum and
  s0exp0sum0bystudy can be tested. Every filename candidate must be supported
  by the displayed title or Column 1 descriptions.

  Finally, every still-unmatched Set 1 RTF is content-checked against every
  still-unmatched Set 2 RTF, even when the names are unrelated. Only a strong,
  unique title/Column 1 match is accepted. The report says when this complete
  search found no safe match. Ambiguous or rejected files remain unmatched
  and NO change RTF is created for them.

  Example of a safely paired like-name set:
    Set 1: s0ae0by0outcompe0sei.rtf
    Set 2: s0ae0by0outcompe0aeosi.rtf

------------------------------------------------------------------------
 AUDIT LOG  -  proof of every run (kept automatically)
------------------------------------------------------------------------
  EVERY comparison you run - single file OR a whole folder, INCLUDING runs
  that find no differences - is recorded with a date and time in:

        logs/audit_log.csv

  Open it any time (double-click  5-View-Audit-Log.command ) in Numbers or
  Excel to review, sort, or print proof of which files/folders you checked
  and when. One row per run.

  ** IMPORTANT - KEEP THE FOLDER INTACT **
  The audit log and the saved reports live in the "logs" folder, right next
  to the "R" and "macos" folders. You can move the WHOLE tool folder
  anywhere, but do NOT take individual files out of it - if you do, the tool
  can no longer find "logs" and cannot save your audit trail.

------------------------------------------------------------------------
 ALTERNATIVE  -  drive it from the R console (always works)
------------------------------------------------------------------------
  If you'd rather not use the launchers, open R (or RStudio) and run, with
  your real folder location and forward slashes:

        source("/Users/you/Downloads/Updated-rtf-comparison-tool/R/install_packages.R")   # once
        source("/Users/you/Downloads/Updated-rtf-comparison-tool/R/run_compare_paths.R")  # to compare

  ...then paste the two file paths at the prompts.

------------------------------------------------------------------------
 IF SOMETHING GOES WRONG
------------------------------------------------------------------------
  "Could not find R"  -> install R (see WHAT YOU NEED above), then redo
        Step 1.
  Launcher won't open / "unidentified developer"  -> right-click -> Open
        -> Open. If still stuck, run  chmod +x *.command  (see Step 0).
  "...packages failed to install"  -> check internet and run Step 1 again
        (it is safe to run repeatedly).
  Keep the folder intact - the launchers expect the other files to stay
  in the folder above them.

------------------------------------------------------------------------
 OPTIONAL EXTRAS  (in the "macos" folder)
------------------------------------------------------------------------
  2b-Compare-Using-File-Picker.command  Pick files in a dialog instead.
  2c-Compare-Folders.command             Batch-compare two whole folders.
  3-Run-Tests.command                    Built-in test suite (must show 0 failures).
  4-Generate-Test-Data.command           Creates sample RTF files to try.
  5-View-Audit-Log.command               Open the audit log (logs/audit_log.csv).

  For full details, command-line use, and options, see README.md.
